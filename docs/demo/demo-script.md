# 演示脚本 (Demo Script)

> 角色：普通用户 userA、userB（测试登录）+ 管理员（deploy/.env 账号）。前置：后端已启动、Flyway 建表、可选执行 `db/seeds/dev_seed.sql`。

## 主流程：招领 → 认领 → 审核 → 留言 → 双向确认 → 已归还
1. **userB 登录**（小程序，测试登录输入 `userB`）→ 发布一条 **FOUND**「捡到黑色钱包」。
2. **userA 登录**（`userA`）→ 首页找到该 FOUND → 详情「申请认领」→ 填写私密证明。
3. **userB** → 我的/申请详情 → 「接受」。发布状态变 交接中(HANDOVER)，申请变 待交接。
4. 双方在申请详情**留言**沟通线下交接。
5. **userA** 与 **userB** 分别点「我已完成交接」。两方齐全 → 申请 已完成、招领 已归还。

## 寻物线索流程
1. userA 发布 **LOST**「丢失黑色钱包」。
2. userB 详情「提供线索」→ 提交私密线索。
3. userA 我的/线索（或发布者视角）查看线索 → 可标记 已查看/有帮助/已关闭 → 找回后「标记已找回」。

## 匹配演示
- 打开「丢失黑色钱包」详情 → 「查看匹配候选」→ 展示相反类型候选、分数与命中原因（类别一致/地点相近/时间间隔），并声明"仅供参考，不证明归属"。

## 异常与并发（说明性）
- userA 认领自己的 FOUND → 403 `SELF_CLAIM_FORBIDDEN`。
- 同一用户重复提交 → `ACTIVE_CLAIM_EXISTS`。
- 两个申请并发接受 → 只一个成功（`ClaimConcurrencyIT`，CI 演示）。

## 争议 → 管理员裁决
1. 交接中，userA 在申请详情「发起争议」→ 交接暂停（确认返回 `HANDOVER_PAUSED_BY_DISPUTE`）。
2. **管理员**登录后台 → 争议处理 → 打开争议详情 → **先点击【受理此争议】，之后才能查看受限证据** → 选择裁决：
   - CONTINUE：恢复交接；
   - TERMINATE_REOPEN：关闭本次交接，招领恢复可申请；
   - CLOSE：关闭处理。
3. 审计与维护页可见 `DISPUTE_RESOLVE` 审计记录。

## 后台治理
- 管理员在信息治理下架某发布 → 公开列表/匹配不再出现，历史与审计保留；可按规则恢复。
- 用户治理限制 userB → userB 再发布/申请/留言被拒 `USER_RESTRICTED`。

## 图片演示（A1）
- 发布页可"添加图片"（≤6 张，jpg/png/webp），详情页九宫格 + 点击预览。
- 认领申请、寻物线索可附私密证据图片；仅参与方/发布者在详情页可见（陌生人取该 fileId 返回 404）。

## 会话生命周期演示（B3）
1. 登录后在"我的"页操作正常。
2. 调 `POST /api/v1/auth/refresh`（带当前 Bearer）→ 返回新 token。
3. 调 `POST /api/v1/auth/logout` → 旧 token 再访问 `GET /users/me` 返回 401。

## 后台受理与裁决（B9/C3）
- 管理员在"争议处理"中先"受理此争议"，之后才能点开证据图片预览；未受理点证据提示无权（404）。
- 裁决前显示结果预览文案（继续/终止重开/关闭），二次确认后提交。
