# 风险与决策记录 (Risks & Decisions)

## A. 已冻结的业务默认值（P1 冻结）

> 未获教师/团队新要求前**按下列默认值实现**；变更须经此表记录并同步 SRS/接口/数据/测试。

| 编号 | 问题 | 冻结默认值 | 变更触发 |
|---|---|---|---|
| D-01 | 是否接学校身份认证 | **不接**。正式返回 disabled；测试用 MockProvider；预留 `CampusIdentityProvider` | 学校批准并提供协议/测试环境/授权 |
| D-02 | 微信 AppID/密钥与真机 | 有合法配置则真实登录并实测；否则测试登录跑通业务，记录平台阻塞 | 开发主体与运行环境落实 |
| D-03 | 游客查看权限 | 仅公开列表与公开详情，不能提交线索/留言/认领 | 教师要求全员登录 |
| D-04 | 认领证明 | 证明文字**必填**，证明图片可选 | 团队评审或教师要求 |
| D-05 | 匹配权重 | `S = 0.40C + 0.25L + 0.20T + 0.15K` | 测试误判/漏判显著 |
| D-06 | 留言实时性 | 列表刷新 / 简单轮询，不上 WebSocket | 闭环完成且有余力 |
| D-07 | 寻物线索 | 独立私密 `lost_leads` 流程，与 FOUND 认领严格隔离 | 评审要求扩展双向线索留言 |
| D-08 | 双向交接确认 | 两方均确认且无 OPEN 争议才 COMPLETED | 产品评审变更（须重写状态机+测试） |
| D-09 | 重复/重新申请规则 | 同用户对同一招领至多一个有效(PENDING/WAITING_HANDOVER)申请；被拒/关闭的历史保留；招领重开后走**新申请**流程，不复活旧记录 | 团队选择冷却期/申诉规则 |
| D-10 | 编辑限制 | 存在任何有效申请后，禁改招领的类别/时间/地点/核心描述/识别图片；非关键字段可改 | 评审调整 |
| D-11 | 管理员备份权限 | 授权运维触发备份；恢复仅隔离离线命令，无公网一键覆盖接口 | 正式运维安全规范 |
| D-12 | 无权限私密对象请求返回码 | 统一返回 404 避免枚举（文档注明） | — |
| D-13 | 单活跃交接唯一性实现 | 锁定父发布记录 + 条件更新 / 唯一辅助约束（非"先查后插"） | DB 方案评审 |
| D-14 | ID 生成 | 服务端生成、前端不可指定；对外不可枚举 | — |
| D-15 | 时间存储 | DB 存 UTC，API 输出 ISO 8601 带时区；区分丢失/拾取/发布时间 | — |
| D-16 | 正式面向全校发布 | **不作为已完成承诺**；单列微信主体/类目/域名/隐私/审核条件 | 获准公测/运营 |

## D. 技术风险
1. 无微信 AppID → 真实登录链路无法端到端验证。
2. 并发一致性（单活跃交接/双向确认/争议竞态）实现与测试难度高。
3. 跨模块接口耦合 → 已在 P1 冻结契约与事务所有者缓解。
4. 真机/性能/备份恢复受环境限制 → 如实标注"待验证"。
